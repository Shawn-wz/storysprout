# StorySprout 项目报告

- 报告日期：2026-11-19（Asia/Shanghai）
- 实验记录范围：截至本报告编写时已保存的本地训练、评估和数据审查产物
- 项目状态：阶段性完成，暂停新增训练与实验

## 摘要

StorySprout 是一个以 TinyStories 为主要预训练语料的小型英文故事语言模型项目。项目实现了约 735 万参数的 decoder-only Transformer，完成了数据准备、分词、预训练、监督微调（SFT）、奖励模型与 GRPO 流程，并围绕故事中的人物归属、状态变化和叙事一致性进行了多轮对照实验。

全量清洗数据包含 1,689,700 篇故事。模型从随机初始化训练一轮，处理 325,448,604 个有效目标 token，在统一故事验证集上取得 1.830930 的交叉熵和约 6.2397 的困惑度。相同验证口径下，50 万篇单轮训练的 loss 为 1.999352，10 万篇五轮训练为 2.032513。

语言预测的改善没有自动转化为可靠的故事逻辑。全量底座在反复使用的 384 道人物归属开发题上为 53.4%。专项状态 SFT 将其提高到 77.1%，但普通故事验证 loss 上升到 2.1328。追加 GRPO 对困难组合泛化有局部收益，相对继续 SFT 的总体优势很小。最后的混合训练通过普通故事回放保留了语言预测表现，一致性续写监督也改善了熟悉条件下的状态问答，但未显示可靠的开放故事质量提升。

本项目形成的阶段性成果是完整的实现、可追溯的实验记录和对能力边界的测量。现有结果支持暂时收尾，不支持宣称故事逻辑已解决、模型能力已达上限，或 RL 已成为有效的通用修复方法。

## 1. 目标、范围与研究问题

### 1.1 项目目标

1. 实现并理解小型自回归语言模型的完整训练流程。
2. 在有限算力下训练能够生成英文儿童故事的模型。
3. 分别测量语言预测、指令格式适配、关系追踪和开放故事生成。
4. 用对照实验检验数据量、上下文、参数分配、优化配置及后训练的作用。
5. 保留数据清单、配置、权重、评估输出和限制，便于后续复查。

本阶段以学习与实验验证为主要目标，尚未达到可靠故事生成产品的质量要求，也不是对 TinyStories 原论文的严格复现。

### 1.2 核心问题

|问题|本阶段得到的回答|
|---|---|
|更多语料是否有效|改善了普通语言预测，收益与训练计算增加存在耦合|
|等更新预算下，新故事是否比重复旧故事更有帮助|本次 50 万篇单轮优于 10 万篇五轮，但来源构成和质量仍有耦合|
|增加注意力容量、减少 FFN 是否更好|当前单轮实验未显示稳定优势，较深结构仅有小幅 loss 改善|
|优化配置是否能明显改善结果|本次联合调整没有优于 A 组，不能推出其他配置都无效|
|SFT 能否改善状态追踪|能，主要体现在受控任务和熟悉表达上|
|RL 是否优于直接监督|困难分布外题有局部收益，总体没有形成明确优势|
|问答改善是否迁移到自然故事|目前没有可靠证据|
|是否可以阶段性结束|可以，保留结果和边界即可，无需为收尾继续训练|

## 2. 系统实现

### 2.1 模型与参数

基准模型配置如下，架构实验中的变体另行列出。

|项目|配置|
|---|---|
|模型类型|decoder-only、自回归、因果注意力|
|词表|8,192，byte-level BPE|
|隐藏维度|256|
|Transformer 层数|4|
|注意力头|4 个，每头 64 维|
|FFN 中间维度|1,024|
|FFN 激活|ReLU|
|位置编码|RoPE，base 为 10,000|
|默认上下文|256 token|
|输入与输出词矩阵|不共享权重|
|归一化|每个块的两个子层共用同一个 LayerNorm，无输出前 final LayerNorm|
|可训练参数总数|7,347,200|

参数分布为输入词嵌入 2,097,152、输出投影 2,097,152、Transformer 块合计 3,152,896。输入、输出词矩阵约占总参数的 57.1%。讨论容量时需要区分总参数和真正参与逐层上下文处理的主体参数。

实现保留了已有权重依赖的结构约定。共用 LayerNorm 等设计是当前实现的事实，尚未通过独立消融确认其收益或代价，不能直接认定为错误根因。

源代码见 [model.py](../codes/model.py) 与 [config.py](../codes/config.py)。

### 2.2 训练目标与数据边界

预训练使用 next-token 交叉熵。输入与目标只进行一次因果位移，padding 不计入 loss。SFT 使用以下序列格式，只监督回答与 EOS，prompt、角色前缀和 padding 对应标签为 `-100`。

```text
<bos><user>{prompt}<assistant>{response}<eos>
```

故事续写与聊天式短答属于不同输入分布。直接给预训练模型套上短答格式，会把格式适配不足混入能力测量，因此后文同时报告候选人名比较、自由短答和普通故事表现。

### 2.3 工程组成

|部分|作用|
|---|---|
|数据与 tokenizer|原始故事转换、BPE、清洗、去重、分词缓存和指纹|
|预训练与 SFT|共享训练、验证循环，按阶段配置监督标签|
|奖励模型|基于语言模型骨干学习 chosen/rejected 偏好|
|GRPO|组内相对奖励、策略裁剪、冻结参考策略，无 critic|
|checkpoint|保存模型配置、权重、优化器状态、训练步数及 tokenizer 指纹|
|实验工具|固定预算对照、状态任务生成、数据审查、汇总与生成比较|
|测试|数据编码、因果标签、生成、续训、奖励模型及混合 token 预算等检查|

checkpoint 加载兼容当前与旧格式。预训练续训恢复优化器状态并创建新运行目录；SFT 从来源权重开始使用新优化器。旧权重可能缺少 tokenizer 指纹或完整续训元数据，不能把格式兼容等同于训练过程可逐位重现。

## 3. 数据、环境与可追溯性

### 3.1 TinyStories 与 tokenizer

沿用项目已有 tokenizer，在原始本地 10 万篇训练故事上学习 BPE，后续对照不重新训练 tokenizer。特殊 token 包括 PAD、UNK、BOS、EOS、USER 和 ASSISTANT。

全量数据来自官方默认训练集的四个 Parquet 分片，固定 revision 为 `f54c09fd23315a6f9c86f9dc80f725de7d8f9c64`。

|清洗步骤的排除项|故事数|
|---|---:|
|原始故事总数|2,119,719|
|疑似乱码或控制字符等问题|130,085|
|空白|230|
|规范化后重复|299,046|
|与现有验证集重合|658|
|最终保留|1,689,700|

排除项按处理流程依次统计，彼此不重复计数。清理包含 Unicode NFC、首尾去空白、规范化空白去重和验证集去重，不包含语义近似去重、人物状态核验或完整故事质量审核。

验证集沿用 2,000 篇故事，其中去除疑似乱码及非法内容后的子集为 1,886 篇。这个子集没有逐篇语义标注，不能称为逻辑正确的金标准集。

全量数据准备清单见 [tokenized_manifest.json](../data/tinystories_full/tokenized_manifest.json)，启动设置见 [training_config.json](../data/tinystories_full/training_config.json)。

### 3.2 上下文截断与有效 token

训练缓存每篇最多保留 `[BOS] + text + [EOS]` 的前 257 个 token，构成最多 256 个预测目标。超出的尾部不作为其他窗口继续训练，完整文本仍保留在 JSONL 中。

|项目|数量|
|---|---:|
|每轮有效训练目标 token|325,448,604|
|缓存中存储的训练 token|327,138,304|
|被缓存截断的故事|311,141，约 18.41%|
|保留 EOS 的故事|1,378,559|
|统一验证目标 token|366,546|

有效目标 token、输入 token、不同故事数和累计更新次数是不同预算。后训练中的 prompt 输入不计入回答监督量，但仍占用计算，不能用目标 token 相同推断 FLOPs 相同。

### 3.3 训练环境

本地历史审查记录显示使用 NVIDIA GeForce RTX 5060 Laptop GPU，显存约 7.96 GiB。已有 Python 环境为 `storysprout_env`，项目记录采用 Python 3.11。依赖快照包括 PyTorch `2.10.0+cu128`、tokenizers `0.23.3`，其余版本见 [requirements.txt](../requirements.txt)。硬件、依赖、数据缓存和实现都会影响耗时，报告中的训练时间仅描述该次本地运行。

## 4. 评估方法

### 4.1 普通语言预测

报告原验证集的平均目标 token 交叉熵，以及过滤后的验证子集 loss。困惑度为交叉熵取指数。只有 tokenizer、文本、目标覆盖等条件相同的 loss 才能直接比较。

512 上下文组同时报告自身上下文和统一前 256 个目标 token 的指标。本报告跨组表格优先使用统一 256 口径。SFT 回答 loss 与普通故事 loss 使用不同目标分布，不混在一张学习曲线中解释。

### 4.2 384 道人物归属开发题

题目覆盖 8 对姓名、4 件物品、gave/got 两种交接表述、姓名交换和三个距离，比较固定故事前缀下两个单 token 候选姓名的分数。实际事件后间隔为 18、78、161 token。补充相邻题的间隔为 5 token。

姓名互换后均正确比单条正确更能抑制固定人名偏好。该测试只覆盖一个模板族，长期用于开发，专项训练也接触了相关姓名与交接词，因此不是最终独立基准，不能把正确率解释为完整故事的逻辑正确率或模型记忆距离上限。

### 4.3 新状态问答与自由叙事

专项数据包含物品持有者和位置两类状态，由事件重放器确定标签。保留题扩展到多次变化、干扰物品、未见表达、人名及其组合，模型从完整词表自由生成短答，而非限定候选集合。

自由故事评估保留原始续写、解码参数与停止原因。最后一轮使用 24 个新故事开头，每个模型生成 48 条输出；另对预先指定的 12 个开头进行隐藏模型标签的单助手审阅。它是小样本定性证据，没有独立人工评审或稳定总体排名的效力。

## 5. 早期训练与流程验证

### 5.1 早期预训练轨迹

早期 checkpoint 包含不同数据规模和学习率的多阶段历史。已有日志中的验证 loss 从 2.3192 逐步降到 2.09897、1.93126、1.87296，最终用于早期 SFT 的底座为 1.852605，累计 157,500 次更新。另有学习率不同的分支记录为 2.02120。

这些是历史开发轨迹，不能整理成同一设置下的独立等预算实验，也不应将 checkpoint 标记的 15 个累计 epoch 理解为完整 TinyStories 训练了 15 轮。后续数据与结构消融采用从头初始化的新实验以减少历史耦合。

### 5.2 故事指令 SFT

最初 pilot 为 32 条训练、8 条开发样本，扩展版为 200 条训练、同样的 8 条开发样本，另有 20 个开发生成提示。回答为助手编写的合成故事，没有独立人工审核。

200 条版本训练 3 轮后的开发 loss 为 3.0877；另一轮 20-epoch 试验中，第 6 轮开发 loss 最低，为 3.0067，第 20 轮训练 loss 降到 0.4121，开发 loss 升至 3.3541。生成可以学会短回答和结束格式，但仍有角色替换、重复与事件偏离。这说明小样本格式适配不等同于广泛故事质量提升，也提供了过拟合风险的具体记录。

数据说明见 [SFT v1](../data/sft_v1/README.md)，诊断见 [更长训练对照](sft_v1_longer_training_comparison.json)。

### 5.3 学习奖励模型与首轮故事 GRPO

奖励数据按 prompt 划分，训练 160 个、验证 40 个、测试 8 个 prompt，每个构造四对偏好，共 640、160、32 对。负例来自实体替换、离题回答、重复结尾与删除结尾，标签是规则构造的偏好假设。

奖励模型训练 3 轮，验证偏好准确率从 48.75% 提高到 75.625%，测试为 56.25%。测试 prompt 很少，且源示例与早期 SFT 存在接触，不能据此证明奖励模型能可靠评判故事逻辑。

首轮故事 GRPO 使用冻结的 SFT 参考与该奖励模型，batch 为 2 个 prompt、每组 4 个回答、最多 64 个新 token、学习率 1e-5、KL 系数 0.04，完成 100 次更新。这一阶段验证了流程运行，没有独立故事评测证明生成质量提升。训练 reward 的尺度及数值不是故事正确率。

这一条“学习奖励模型”的流程，与后续“可验证状态任务的规则奖励”实验不同，不能混用两者的分数和结论。奖励模型结果见 [summary.json](../models/reward_run_20261118_002839_831482/summary.json)。

## 6. 预训练消融实验

### 6.1 数据规模、清洗与上下文

五组均使用相同可训练参数初始化、tokenizer、batch size 8、Adam 默认参数、固定学习率 3e-4、seed 2026，训练一轮。

|组别|训练故事数|上下文|有效目标 token|更新次数|统一验证 loss|过滤验证 loss|
|---|---:|---:|---:|---:|---:|---:|
|control，原数据|100,000|256|19,232,586|12,500|2.2882|2.2722|
|A，清洗补齐|100,000|256|19,162,135|12,500|2.3825|2.2885|
|B，与 A 同故事|100,000|512|21,374,890|12,500|2.3727|2.2795|
|C，扩充数据|500,000|256|96,262,605|62,500|1.9994|1.8969|
|D，与 C 同故事|500,000|512|107,779,557|62,500|2.0023|1.9000|

50 万篇组有明显语言预测收益，但同时增加了计算。512 上下文没有在统一 256 验证口径下形成一致优势。清洗补齐的 A 也未优于原数据 control，因此不能宣称这套清洗流程本身已经提高模型效果。

结果与数据构成见 [五组实验结果](../experiments/data_context_20261117/results.md)。

### 6.2 注意力与 FFN 参数分配

三组使用 A 的相同数据、顺序、目标 token 和更新次数。总参数约保持不变，但实际计算量随结构变化。

|组别|层数|头数 × 每头维度|FFN 维度|总参数|验证 loss|人物归属|
|---|---:|---|---:|---:|---:|---:|
|A|4|4 × 64|1,024|7,347,200|2.382498|199/384，51.8%|
|3|4|8 × 64|512|7,345,152|2.389815|196/384，51.0%|
|4|6|4 × 64|512|7,347,712|2.363815|184/384，47.9%|

第 3 组保持每头 64 维，因此增加了注意力内部总宽度，并不只是把原来的 256 维分成更多头。它将 FFN 参数转移到注意力投影后，没有获得更好结果。第 4 组加深同时缩小 FFN，语言预测略有改善，人物归属没有同步改善。

这是一次单种子、单轮、固定更新预算的比较，不能推出注意力容量无用、FFN 必须保留某一比例，或更深模型没有潜力。详情见 [架构结果](../experiments/architecture_20261118/results.md)。

### 6.3 优化配置

优化组保持 A 的结构、初始化、故事顺序和预算，联合改变 Adam 的 beta2、学习率曲线和梯度裁剪。

|设置|A|优化组|
|---|---|---|
|Adam beta|0.9，0.999|0.9，0.95|
|学习率|固定 3e-4|峰值 1e-3，末尾 1e-4|
|调度|无|625 步线性预热，随后余弦衰减|
|梯度范数上限|无|1.0|
|验证 loss|2.382498|2.388649|
|人物归属|51.8%|46.6%|

本次联合配置没有改善结果。它未隔离每个选项的贡献，也没有测量长训练后的最优收敛。共享训练函数通过可选参数接受 scheduler 和梯度裁剪，原调用方式仍可使用。详情见 [优化实验](../experiments/optimizer_20261118/results.md)。

### 6.4 10 万篇五轮与 50 万篇单轮

|设置|不同故事数|累计更新|有效目标 token|验证 loss|人物归属|
|---|---:|---:|---:|---:|---:|
|C，单轮|500,000|62,500|96,262,605|1.999352|59.6%|
|10 万篇，五轮|100,000|62,500|95,810,675|2.032513|47.7%|

两组具有相同初始化和更新次数，目标 token 相差约 0.469%。10 万篇的逐轮验证 loss 为 2.3825、2.1930、2.1083、2.0631、2.0325，重复训练持续有效，但最终仍不及 C。

该结果支持本次预算下增加不同故事的价值。10 万篇为 50 万篇的前缀子集，来源构成也不同，仍不足以把数量与语义质量完全分离。详情见 [重复数据实验](../experiments/repeated_data_20261118/results.md)。

## 7. 全量预训练

### 7.1 设置与结果

全量模型从随机初始化开始，默认 4 层结构，固定学习率 3e-4、Adam 默认参数、batch size 8、seed 2026、256 上下文、FP32，一轮完成 211,213 次更新。日志耗时 4,278.1 秒，约 71.3 分钟。

|模型|累计更新|原验证 loss|PPL|过滤验证 loss|人物归属|
|---|---:|---:|---:|---:|---:|
|C|62,500|1.999352|7.3843|1.896898|59.6%|
|10 万篇五轮|62,500|2.032513|7.6332|1.927592|47.7%|
|早期多阶段底座|157,500|1.852605|6.3764|1.835915|54.2%|
|全量单轮|211,213|1.830930|6.2397|1.731690|53.4%|

全量单轮相对 C 的原验证 loss 下降约 8.42%，累计目标 token 约为 C 的 3.38 倍。这里同时增加了语料覆盖与训练计算。best 与 epoch_1 是相同内容，只有一个最终轮验证记录，不能据此判断已经收敛。

### 7.2 关系追踪与生成错误

全量模型在 18-token 间隔下，gave 题为 13/64，got 题为 60/64。这与偏好交接句主语的捷径相符。移除环境描写后仍只有 54.7%，说明失败不只发生在长距离。

同条件自由续写中仍出现狗寻找狗、青蛙感谢青蛙、寻找球转向反复玩滑梯等现象。它们表明局部语言流畅不能保证人物、目标和因果连续。四个已知开头只是开发样例，不足以估计整个分布的错误率。

证据见 [全量评估分析](full_pretrain_20261118/analysis.md)、[完整指标](full_pretrain_20261118/results.md) 和 [生成对照](full_pretrain_20261118/generations.md)。

## 8. 可验证状态任务的 SFT 与 GRPO

### 8.1 设计

以全量底座为共同起点，生成 8,192 道训练题、512 道开发题和独立保留测试。任务包含物品归属、位置、交接与移动，并加入无关实体干扰。标签由独立事件重放核验，跨集合 prompt 去重。

专项 SFT 使用 batch size 16、学习率 1e-4，训练六轮，按开发贪心精确正确率选模。选中第 5 轮，累计 2,560 次更新，开发正确率 98.8%。

继续 SFT 与 GRPO 均从这一权重开始，匹配 1,600 个提示组、12,800 个回答槽位和 400 次更新。GRPO 每组 8 个回答、最多 4 个 token、全词表采样、KL 系数 0.02、裁剪 epsilon 0.2、学习率 1e-5，奖励为正确的单个人名或位置。继续 SFT 使用相同提示及正确答案。

这是匹配提示与更新预算，GRPO 额外需要采样及策略前向计算，并非等计算量对照。

### 8.2 第一轮结果

|指标|全量底座|专项 SFT|继续 SFT|GRPO|
|---|---:|---:|---:|---:|
|保留短答测试，1,120 题|2/1,120|859/1,120，76.7%|871/1,120，77.8%|872/1,120，77.9%|
|原人物归属开发题|205/384，53.4%|296/384，77.1%|292/384，76.0%|293/384，76.3%|
|原故事验证 loss|1.8309|2.1328|2.1426|2.1315|

底座未适配聊天短答格式，不能把 0.2% 到 76.7% 全部解释为关系推理改善。原人物归属测试保持故事续写格式，它也有提升，支持专项训练确实调动了关系识别能力，但该开发模板有熟悉性影响。

第一轮 GRPO 平均奖励约 98.7%，只有约 2.2% 的组同时出现正确和错误答案，400 次更新中仅 34 次出现这类组。组内优势信号接近饱和，GRPO 比继续 SFT 只多答对一道题，不能用来支持普遍优势。

### 8.3 追加困难任务

针对奖励饱和，另外从同一专项 SFT 权重出发，比较困难 SFT 与困难 GRPO。任务包括 3–5 次状态变化、更长干扰和独立物品，prompt 不超过 244 token。两分支均为 400 次更新，在训练结束后统一评估新增的 640 道题。

|新增难题|专项 SFT 起点|困难继续 SFT|困难 GRPO|
|---|---:|---:|---:|
|同分布，320 题|206/320，64.4%|290/320，90.6%|274/320，85.6%|
|专项未见人名与句式，320 题|38/320，11.9%|77/320，24.1%|96/320，30.0%|
|合计|244/640，38.1%|367/640，57.3%|370/640，57.8%|

GRPO 的分布外收益为多答对 19 道，同时在同分布少答对 16 道，合计只多 3 道。按固定题目配对自助抽样，分布外差异的 95% 区间约为 +2.8 至 +9.1 个百分点，总体为 -1.7 至 +2.5 个百分点。区间没有覆盖训练种子变化和多重比较。

分布外持有人题仍很弱，困难 SFT 为 3/160，困难 GRPO 为 16/160。困难 GRPO 的奖励差异组占比上升到 14.6%，表明这次确有更多有效组内信号，但尚未形成可靠的复杂关系泛化。

### 8.4 对故事生成的影响

困难 SFT 与困难 GRPO 的普通故事 loss 分别为 2.1256 和 2.1359，均高于原底座。生成中仍存在名字替换和过早结束。短答训练没有加入普通故事回放，且 RL 参考是专项 SFT 权重，因此 KL 约束不能直接恢复专项训练前的故事分布。

这一阶段的结论是专项 SFT 提供了主要任务收益，RL 有局部迁移迹象，但没有解决自由叙事的逻辑问题。详情见 [状态实验分析](../experiments/state_rl_20261118/analysis.md) 和 [困难任务结果](../experiments/state_rl_20261118/hard_results.md)。

## 9. 叙事数据质量审查

审查读取了实际全量训练 JSONL。固定种子均匀抽取 48 篇完整故事逐篇阅读，另对全量文本执行词法扫描和定向候选检查，两类抽样分开解释。

观察到了物品归属写反、事件与结尾教训不符、原文半句中断等可复查问题。例如清洗后索引 1,376,025 的交换玩具故事存在归属冲突，索引 1,223,003 的故事在服从要求后套上不相符的教训；这些内容在训练保留区间内。与此同时，样本也包含关系基本一致的故事。

词法扫描发现交接与感谢并不少见，但人物归属题所用 `was/is now with` 显式复述句式仅命中 8 篇。这个差异提示测量还包含表达方式迁移，不能把命中率解释为完整状态监督的密度。正则也会误报，不能替代语义审核。

48 篇属于问题发现样本，不据此推算全量逻辑错误率。18.41% 的训练缓存截断是另一项可确认的信号损失，其性能代价没有独立量化。现有证据不支持把预训练数据质量认定为唯一或最主要瓶颈。

全文、逐项判读和扫描定义见 [叙事数据审查](narrative_data_audit_20261118/analysis.md)。

## 10. 普通故事回放与一致性续写的混合训练

### 10.1 设计与预算

两个分支重新从全量预训练底座出发，均采用 Adam 默认参数、学习率 1e-4、梯度范数上限 1.0，完成 2,000 次更新，每次精确监督 1,000 个目标 token，固定以第 2,000 步权重评估。

|分支|普通故事目标|状态 QA 目标|一致性续写目标|
|---|---:|---:|---:|
|control|1,800,000，90%|200,000，10%|0|
|mixed|1,200,000，60%|200,000，10%|600,000，30%|

使用 16,384 篇普通故事回放、32,768 条 QA 池与 8,192 条续写池。两组共享每次更新的 60% 普通故事与 10% QA，实验组以一致性续写替代另外 30% 普通故事。微批次为 16，按有效目标数累积梯度。

两组输入 token 分别为 12,642,251 和 13,621,413，每组约 4.3 分钟。因此它是等监督目标预算的替换实验，不是等输入计算实验。对照没有纯普通故事续训分支，不能独立估计 QA 或回放各自的因果贡献。

### 10.2 语言预测与状态问答

|指标|全量底座|control|mixed|
|---|---:|---:|---:|
|原故事验证 loss|1.8309|1.7948|1.8078|
|过滤验证 loss|1.7317|1.6991|1.7140|
|原 384 题开发正确率|53.4%|66.1%|77.9%|
|新同类 QA，240 题|未适配短答格式|65.0%|87.9%|
|新组合泛化 QA，240 题|未适配短答格式|13.8%|13.8%|

两个混合分支都没有重现单一短答 SFT 的明显语言建模退化。普通故事回放与保留语言预测表现相符，但与之前实验相比还改变了预算和数据，不能精确归因。

一致性续写替换对熟悉条件下的 QA 有收益，在新名字、新问句和长间隔组合上没有收益。mixed 的组合泛化持有人题仅 2/120，位置题为 31/120。所谓未见姓名指专项合成训练没有使用，普通故事回放可能出现过这些名字。

### 10.3 模板拟合与错误状态填充

一致性续写开发 loss 从底座的 2.9068 降到 mixed 的 0.1031，但新前缀中，钥匙最终已到 Emma 手里，模型仍写到前缀未出现的 Max 手中。模型能够很好地拟合语言骨架，同时填入错误实体。

48 个受控前缀各生成两次，mixed 的 96 条中有 30 条含检查器可解析的显式状态，其中 9 条核验一致、21 条检测到矛盾。底座仅覆盖 1 条，对照覆盖 0 条。覆盖率差异太大，不能将 9/96 解释为整体故事正确率，也不能把未覆盖输出当作错误或通过。

### 10.4 开放故事审阅

24 个新开头各生成贪心与 temperature 1.0 续写，每模型 48 条，预算 160 个新 token，三组都没有少于 20 token 的输出。事件清单式受控前缀仍可能出现短输出，保留效果依赖输入分布。

对预先指定的前 12 个开头贪心输出隐藏模型名称、打乱顺序审阅，结果如下。

|模型|明确矛盾|矛盾不确定|推进原情节|连贯结尾|三项均满足|
|---|---:|---:|---:|---:|---:|
|底座|9/12|0/12|6/12|2/12|1/12|
|control|7/12|1/12|6/12|2/12|1/12|
|mixed|8/12|1/12|3/12|2/12|1/12|

三项均满足指无明确矛盾、推进原情节且结尾连贯，不确定案例不计入。模型映射在评分保存后才用于汇总，但评审只有同一助手一次，没有独立人工标注。结果没有显示 mixed 的开放故事优势，也不足以给出稳定总体排序。

协议、完整输出与评分理由见 [混合实验分析](../experiments/story_mix_20261118/analysis.md)、[结果](../experiments/story_mix_20261118/results.md) 和 [审阅记录](../experiments/story_mix_20261118/blind_ratings.json)。

## 11. 与 TinyStories 原论文的关系

原论文的较大模型展示了更好的故事连贯性，但小模型同样有明显失败。在梯子倒下、Lucy 被困的同一开头下，8.3M、8 层模型继续写帮助她爬梯子，一致性评分为 5/10；28M、8 层模型写出救援，得分 9/10。这只是单个样例。论文用约 50 个开头、每题 10 次生成和 GPT-4 评分进行总体评估，与本项目的任务正确率不可直接比较。[原论文](https://arxiv.org/html/2305.07759v2)

作者公开的 TinyStories-8M 配置为 256 维、8 层、16 个头、GELU、全局与局部注意力交替，词表为 50,257。仅输入词矩阵就约 1,287 万参数，说明模型名称不能作为与本项目 735 万总参数直接对齐的统计。按照标准 GPT-Neo 块结构估算，其 Transformer 块约有 631 万参数，约为本项目主体的两倍。这个估算来自配置，未在本项目加载作者权重实测。[作者配置](https://huggingface.co/roneneldan/TinyStories-8M/blob/main/config.json)

论文报告训练上下文 512、只保留最常见 10K token，而发布配置仍为完整词表，位置容量为 2,048。这些口径需要区分。固定隐藏维度时增加头数通常不增加投影总参数；本项目第 3 组则额外保持了每头维度，属于另一种改动。不能从头数差异直接判断性能原因。

官方说明另区分原始训练文本与更大的 GPT-4-only V2。项目使用默认 Parquet 数据，未证明与论文原始文本逐项等价。[官方数据说明](https://huggingface.co/datasets/roneneldan/TinyStories/raw/main/README.md)

因此，目前没有证据把 StorySprout 的结果认定为同规模模型的上限。架构、训练充分程度、数据版本和评估方法尚未对齐，作者公开权重也尚未完成同题测试。

## 12. 综合结论与限制

### 12.1 本阶段支持的结论

1. 当前实现能够在本地算力上完成预训练及多种后训练流程，产物可用于复查。
2. 在已测预算下，扩大不同故事覆盖有语言预测收益，重复小数据也有效，但不是完全等价的替代。
3. 当前结构和优化配置消融没有带来可靠的故事逻辑升级。
4. 模型仍能通过专项监督学习状态识别，不能把底座的低分解释为结构绝对没有这种表达能力。
5. 问答、模板续写与开放故事生成之间存在明显迁移缺口。
6. GRPO 对某些分布外难题有局部收益，但没有展示总体或故事质量上的明确优势。
7. 回放普通故事的混合方案保留了普通语言预测表现，但仍未解决新实体和新表达的组合泛化。

### 12.2 尚不能成立的结论

- TinyStories 数据质量是逻辑错误的唯一或主要根因。
- 735 万参数模型已经达到容量上限，或者预训练已经没有收益。
- 只要增加头数、加深网络或减少 FFN 就能解决问题。
- 开发正确率接近 80% 意味着约 80% 的自然故事逻辑正确。
- loss 更低意味着人物、物品与因果关系一定更可靠。
- 已与原论文达到公平对齐，或已复现原论文效果。

### 12.3 主要限制

实验主要使用单个训练种子；没有覆盖训练随机性的稳定性验证。原验证集与人物题被反复用于开发，存在选择和熟悉性影响。部分比较同时改变数据、目标、计算与格式。合成状态任务覆盖有限，跨 prompt 去重不等同于跨语义模板独立。规则检查器覆盖率不同，助手审阅样本很小。全量只有一轮最终验证，未完成收敛分析，也未进行严格 FLOPs 对齐或作者权重基准测试。


### 14.2 已有底座续写

以下示例只加载现有权重并采样，不训练。`generate` 接受正数 temperature；贪心评估使用实验工具内的 argmax 实现，不能向这里传 0。

```python
from pathlib import Path

from tokenizers import Tokenizer

from codes.checkpoint import load_checkpoint
from codes.generate import generate

root = Path.cwd()
tokenizer_path = root / "artifacts" / "tokenizer.json"
tokenizer = Tokenizer.from_file(str(tokenizer_path))
model, metadata = load_checkpoint(
    root / "models" / "run_20261118_183053_375283" / "best.pth",
    device="cpu",
    tokenizer_path=tokenizer_path,
)
print(generate(
    model,
    tokenizer,
    "Once upon a time, a little girl found a red ball.",
    max_new_tokens=96,
    temperature=0.8,
    seed=2026,
))
```

总上下文包含 BOS、prompt 与新增 token，达到 256 时停止。聊天式 SFT 需要按训练时的角色前缀编码，不能把普通续写接口直接当作聊天接口。

## 15. 如未来恢复，尚待回答的问题

以下为候选研究方向，均未作为已完成结果，也不要求现在继续。

1. 用作者公开权重与 StorySprout 在同一组保留故事上比较，核对实际参数统计。
2. 建立更接近论文的结构和上下文基线，独立测量深度、归一化与权重共享。
3. 在同一来源和目标 token 预算下拆分语义质量、故事截断与训练充分程度。
4. 扩大人名和表达覆盖，使用自然叙事中的关系监督，并引入独立人工故事审阅。
5. 只有在保留故事表现、奖励可验证且基线充分时，再检验 RL 的附加价值。
