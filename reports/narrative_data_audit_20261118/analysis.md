# TinyStories 人物关系与情节逻辑审查

日期：2026-11-18。

## 判断

实际训练语料中确实存在人物归属写反、教训与事件不相符、因果解释薄弱和原文不完整的问题。数据质量值得作为后续实验变量，但现有证据不能证明它是 StorySprout 逻辑薄弱的主要原因，更不能认定 TinyStories 普遍缺乏连贯性。

这里要区分三个问题：原文有没有错、原文是否提供足够强的关系追踪信号、训练过程是否保留了这些信号。它们需要分别检查。

## 检查范围与复现

- 检查本地全量预训练实际使用的 `data/tinystories_full/train.jsonl`，共 1,689,700 篇；逐字节 SHA-256 与训练准备清单一致：`970f76cf4bf193538dba35a0d7ea81f3fe2e429d23960576119892a1353a8380`。
- 固定种子 20261118，通过 `random.sample(range(1689700), 48)` 均匀无放回抽取 48 篇，由本次助手逐篇阅读完整文本。编号均为清洗后 JSONL 的 **0-based 行索引**，实际文件行号需加 1。
- 对全体故事执行词法扫描，另外阅读全部 3 个同名感谢/帮助候选。定向候选与均匀样本分开，不混算问题比例。
- 全文、token 长度、256-token 训练前缀见 `uniform_sample.json`，便于阅读的全文见 `uniform_sample.md`；逐篇阅读备注见 `manual_review.json`。
- 运行 `python -m tools.audit_narrative_data` 可重新扫描并抽样。手工判读记录独立保存，程序不自动判定逻辑质量。
- 这不是双人盲标或大样本质量评测。未发现问题不等于证明正确；不由这 48 篇推算整个语料的逻辑错误率。

## 1. 来源和现有清理未保证叙事正确

训练清单指向官方默认数据的四个 Parquet 分片，版本为 `f54c09fd23315a6f9c86f9dc80f725de7d8f9c64`，并非单独下载的 `TinyStoriesV2-GPT4-train.txt`。

[官方数据说明](https://huggingface.co/datasets/roneneldan/TinyStories/blob/main/README.md)明确说明原版由 GPT-3.5 与 GPT-4 生成，并称其中 GPT-3.5 文本质量较低，另提供 GPT-4-only V2。本地文本只有 text 字段，无法将某一篇错误归因到某个生成模型。

原始 2,119,719 篇中，准备清单记录排除 130,085 篇疑似乱码、230 篇空白、299,046 篇重复、658 篇与验证集重合的文本。这些是按流程依次判定的排除项。

检查 `tools/data_ablation.py` 和 `tools/prepare_full_data.py`：清理包含 Unicode 标准化、strip、乱码/控制字符过滤、规范化空白去重和验证集去重；没有人物状态、事件前提、因果、原文结尾完整性检查。去重也没有消除语义相近的叙事模板。

## 2. 随机样本中可复查的实际问题

### 人物与物品对应写反：索引 1,376,025

原文先设定 Jen 喜欢在自己的椅子上摇，Sam 玩自己的腰带；然后宣布两人交换玩具。交换后的段落却继续写 Jen 在椅子上摇、Sam 玩自己的腰带，并称椅子为 Sam 的。之后 Sam 向 Jen 要回腰带，Jen 向 Sam 要回椅子。

前文描述的实际持有者，与后文要回玩具的对象相冲突。这是与物品归属测试直接相关的训练文本噪声。故事 261 个文本 token，相关冲突在前 256 token 内，模型确实会看到，不能归因于本次缓存截断。

### 事件与教训不相符：索引 1,223,003

妈妈让 Lily 买剃须刀。Lily 想买玩具但最终按要求买了剃须刀，爸爸使用后割伤送医。结尾一方面说她后悔没买玩具，另一方面又总结应该听妈妈的话。

事件已经是服从要求，结尾却套上服从教育；正文与寓意没有合理衔接。此故事 180 个文本 token，整篇都保留在训练缓存中。

### 因果解释不足，需保留判读余地

- 索引 1,195,418：瓶子掉进水坑，因“湿了”不能喝水，解决办法是再次泡水再擦干。清洗脏瓶子本可以合理，但原文没有把问题说成污染，呈现的故障与修复机制含混。
- 索引 799,642：用粉笔在地上画画，被直接解释成能让人谦逊，缺少中间事件或解释。
- 索引 453,326：盾牌卡在灌木里，母亲倒开水后就能取出，缺少解除卡住的机制。
- 索引 818,411：太阳使雪人融化后，立即靠重做雪人解决，没有交代温度或地点改变。可能只是儿童故事的省略，不宜直接判成硬矛盾。

这些更接近弱因果或强行串词，不能和人物归属写反等量齐观。会说话的动物、魔法与拟人本身不作为错误标准。

### 原始完整文本就已中断

- 索引 7,168，298 个文本 token，结尾停在 `Jack hugged his dad and said, "It`。
- 索引 112,216，297 个文本 token，结尾停在 `for a long`。

这些缺口存在于完整 JSONL 文本，不是读取 256-token 训练前缀造成。现有清理没有剔除它们。本次不推断中断发生于哪一步上游生成流程。

### 同时存在正面样本

索引 95,358 的送围巾、202,322 的帮小鸟找妈妈、449,838 的小鸟帮兔子找球、480,707 的父母把钥匙交给女儿等，基本保持了帮助者、受益者、物品和目标的一致性。不能因上面几个问题样本就说语料没有提供正确关系信号。

## 3. 全量扫描提示句式覆盖不均，不能替代语义审查

以下计数针对完整 JSONL 原文，**不是仅扫描训练保留的前缀**；正则定义完整保存在 `scan.json`。同一故事最多计一次，各行允许重叠。

|词法信号|命中故事数|占总故事数约|
|---|---:|---:|
|give/gave/gives/given/handed/passed/lent/borrowed/received|389,063|23.03%|
|同一短片段内 gave … to|76,519|4.53%|
|同一短片段内 got/received … from|14,538|0.86%|
|was/is now with|8|0.00047%|
|thank/thanks/thanked/thankful|397,729|23.54%|

这说明交接与感谢并不少见，原人物测试所使用的 `was now with` 明确复述持有人句式却很少见。该测试因此还涉及特定问法的迁移。不能据此否定测试，也不能把其正确率视为全部人物关系能力的无偏测量。

这些正则会遗漏代词、被动语态和大量改写，也会命中与持有关系无关的表达。命中不等于正确示范，更不等于包含多次状态更新；没有命中也不等于没有状态信息。词频只能提示覆盖差异，不能证明复杂状态追踪信号的总体密度。

两个“姓名 thanked 同姓名”与一个“姓名 helped 同姓名”命中全部经过阅读：

- 索引 810,484：开头就有两个都叫 Daisy 的朋友，随后借还物品。实体同名导致表达含混，不能当成严格的自我感谢证据。
- 索引 1,327,778：命中的是 `Ben thanked Ben's mom` 的子串，完整句为 Lily 和 Ben 感谢 Ben 的妈妈，属于正则误报。
- 索引 861,633：孩子与玩具都叫 Spike，帮助关系表达含混；也不能直接判成逻辑上的自我帮助。

因此，本次没有把三个词法命中直接计为三篇角色逻辑错误。

## 4. 本地训练额外丢失了一部分完整情节

当前缓存把 `[BOS] + text + [EOS]` 保留到前 257 个 token，形成最多 256 个预测目标。清单中 311,141 / 1,689,700，即 **18.41%** 的故事被截断，没有保留结尾 EOS。尾部不再作为其他窗口训练。

均匀样本中有 9/48 篇发生缓存截断。例如索引 107,502 的 Sara/Ben 争玩具故事，原文最终写孩子停止争吵并改玩别的玩具，训练前缀却停在他们跟着妈妈去厨房的半句；索引 378,584 的烟火故事，前缀保留到树着火附近，后面的消防员处理和人物反应没有进入训练。

这是真实的训练信号损失，可能使需要后续状态和结果的叙事学习更难。但它的性能影响尚未由独立对照测出，而且不能解释前 256 token 内已经存在的原文错误，或所有短距离关系测试失败。

## 5. 与 StorySprout 已有结果合起来看

`reports/full_pretrain_20261118/analysis.md` 显示全量模型语言验证 loss 改善，但人物归属仍为 205/384（53.4%）；短间隔 gave 题明显弱于 got 题。这符合依赖表面主语等捷径的可能性，但没有给出产生这种行为的唯一原因。

`experiments/state_rl_20261118/analysis.md` 显示相同结构经专项 SFT 后原题达到 296/384（77.1%）。模型有可被专项信号调动的学习空间。但这项比较同时改变了训练目标、格式、数据与训练计算；原题又属于反复使用的开发模板，专项训练接触了相关姓名与交接词。它不能独立证明 TinyStories 原文噪声就是瓶颈。专项训练后故事续写也没有稳定改善。

[TinyStories 原论文](https://arxiv.org/html/2305.07759v2)的生成方法要求简单词汇、随机名词/动词/形容词以及随机叙事特征；公开方法没有描述逐篇用显式状态机核验人物归属。论文对不同规模和深度模型的比较同时说明：同类语料上，小模型先学会语法，而一致性还受模型与训练条件影响。不能由模型错误直接反推出语料同等程度地错误。

## 建议的下一项因果检验

优先把“语义质量”和“截断”拆成两个实验轴，而不是立刻继续增加同类故事数量。

1. 固定模型、tokenizer、训练有效目标 token 预算、学习率安排与解码条件，比较现有清洗数据、等长度分层抽样的 GPT-4-only V2、经过独立叙事审查的子集。GPT-4-only 只作为待测候选，不预设它的人物逻辑已合格。
2. 对同一批来源故事，独立比较当前截断方案与保留完整故事的训练方案；匹配训练 token 预算并记录每篇目标覆盖，避免把增加计算误认为完整性收益。
3. 新建保留测试：多种给出/收到/借还/交换表达、姓名互换、未见姓名、多个物品、状态复述改写；另做自然故事续写的盲评，检查人物、持有者、地点、目标与结果。
4. 对各条件先抽取更大样本做独立复核，给出角色矛盾、因果断裂、原文中断的分项标注；用多训练种子验证差异。现有 48 篇仅用于发现和举证问题。

本次仅进行了数据读取、扫描、tokenizer 检查和报告撰写，没有训练模型或更改数据、缓存与权重。
